# JAM Trail 기능 명세서 (현재 구현 기준)

작성일 2026-09-25 · 앱 버전 1.2.0 · 대상 기기 Garmin fēnix 8 AMOLED (43 mm, 47·51 mm)

이 문서는 **지금까지 구현하고 확인한 내용**을 기능별로 정리한 것입니다.
설계 배경, 조사 근거, 단계별 확인 기록은 `docs/garmin-trail-profile-spec.md`(개발 명세 v3와 그 뒤 수정 기록)에 있습니다.
두 문서가 다르면 이 문서가 현재 동작입니다. (예: 경사 색 3단계, 글자 36 px 이상 레이아웃)

확인 상태 표기: **실기기** = fēnix 8 실기기에서 확인 · **시뮬레이터** = Connect IQ 시뮬레이터(SDK 9.2.0)에서 확인 · **미확인** = 아직 확인하지 못함

---

## 1. 개요

### 1.1 목적
트레일러닝 중 현재 위치 주변의 고도 프로파일을 **어느 구간에서나 같은 가로·세로 축척**으로 보여 줍니다.
가민 기본 앱(ClimbPro 등)은 오르막마다 세로축을 화면에 꽉 차게 늘려서 5% 오르막과 25% 오르막이 비슷해 보입니다.
JAM Trail은 세로 배율을 고정(2×·3×·4×)해 화면의 같은 각도가 항상 같은 경사를 뜻하게 합니다.

### 1.2 제품 형태
- Connect IQ **데이터 필드**, 1필드 레이아웃(전체 화면). `minApiLevel` 5.0.0
- 제품 id `fenix843mm`, `fenix847mm` (51 mm는 47 mm 계열)
- 권한 `Communications` 하나 (코스 파일을 웹 요청으로 받음)
- 개인용 베타 앱으로 스토어에 등록. 앱 ID `ec7e18be-52b0-4eb9-b2ca-cda733808a2d`(처음 시험 필드로 등록한 ID를 이어받음)

### 1.3 사용 흐름
1. 코스 GPX를 저장소 `gpx/` 폴더에 올립니다 (폰 브라우저로 가능).
2. GitHub Actions가 GPX를 변환해 GitHub Pages(코스 서버)에 배포합니다.
3. 전날 집에서 폰을 옆에 두고 트레일런 활동을 열면, 데이터 필드가 폰(Garmin Connect)을 거쳐 코스를 받아 시계에 저장합니다.
4. 달릴 때는 저장된 코스로 그립니다. **폰 없이 동작합니다.**
5. 같은 GPX를 Garmin Connect 코스로도 시계에 넣어 내비게이션을 하면 위치가 가장 정확합니다(선택).

## 2. 시스템 구성

| 구성 요소 | 위치 | 역할 |
|---|---|---|
| 코스 변환기 | `trailgrade/` (Python 3.11+, 표준 라이브러리만) | GPX → 코스 바이너리 → Base64 조각 + 매니페스트 + 코스 목록 + 미리보기 PNG |
| 코스 서버 | GitHub Pages (`https://standardmanual.github.io/589132427/`) | 변환 결과를 정적 HTTPS 파일로 제공. `.github/workflows/pages.yml`이 배포 |
| 데이터 필드 (본 앱) | `app/` (Monkey C) | 코스 받기·저장·복원, 위치 결정, 화면, 설정 메뉴 |
| 시험 필드 | `testfield/` (Monkey C) | 실기기 구조 확인용. 할 일을 마침(더 쓰지 않음) |
| 웹 프로토타입 | `prototype/trail-grade-field.html` | 알고리즘·화면의 기준 구현(브라우저). 변환기와 결과 비교의 기준 |
| 개발 도구 | `scripts/`, `tests/` | 시뮬레이터 실행, 로컬 코스 서버, 위치 시험 재생, 자동 시험 |

데이터 흐름

```
GPX ─push─▶ GitHub Actions(변환기) ─배포─▶ GitHub Pages ─HTTPS(폰 중계, BLE)─▶ 시계 데이터 필드
                                                                                  │ 조각 저장(Storage)
                                                        가민 코스 내비게이션 값 ──┤ 복원 → 위치 결정 → 화면
```

## 3. 기능 명세

### 3.1 코스 변환기 (`python3 -m trailgrade build gpx/`)

| 항목 | 내용 | 확인 |
|---|---|---|
| GPX 읽기 | `trkpt`, 없으면 `rtept`. 고도가 없는 점은 빼고 개수를 보고. 이름은 처음 나오는 `<name>`, 없으면 파일 이름 | 시뮬레이터(자동 시험) |
| 처리 | 20 m 간격 재샘플, 100 m 이동 평균 평활화, 고도 0.1 m 양자화 | 프로토타입과 결과 완전 일치(자동 시험) |
| 구간 분할 | 오르막·내리막·평지. 히스테리시스 20 m, 평지 기준 경사 2%, 500 m 이상 고원 분리, 짧은 구간 흡수(평지 150 m, 오르막·내리막 100 m) | 프로토타입과 완전 일치 |
| 구간 통계 | 길이, 순 고도 변화, 평균 경사, 최대 경사, 유형별 번호 | 일치 |
| 인코딩 | 20 B 헤더 + 고도 u16 + 좌표 i16 델타 + 구간 레코드 10 B (빅엔디언). 100 km 코스 약 30.5 KB | 왕복 복원 시험 통과 |
| 조각 | Base64 6,000자(디코드 4,500 B) 단위, 8의 배수 글자. 100 km 코스 7조각 | 통과 |
| 코스 ID | 바이너리 SHA-256 앞 10자리. 내용이 같으면 ID가 같아 조각 주소가 바뀌지 않음 | 통과 |
| 매니페스트 | `v, id, name, bytes, chunks, crc32, len, gain, loss, emin, emax` | 통과 |
| 코스 목록 | `index.txt` 최신순 최대 20개, `current.txt` = 가장 최근에 올린 GPX | 통과 |
| 미리보기 | 코스 전체 프로파일 PNG(경사 3단계 색, 구간 유형 띠) | 통과 |
| 이름 정규화 | 한글 자모를 완성형(NFC)으로 저장 (맥 파일 이름은 자모 분리형이라 시계에서 깨졌음) | **실기기에서 문제 확인 후 수정**, 자동 시험 |
| 범위 제한 | 고도 0–6,553.5 m(범위 밖은 0으로 자르고 경고), 점 최대 65,535개(20 m 간격에서 1,310 km) | 자동 시험 |

자동 시험 `python3 -m unittest discover -s tests -t .` 20개 통과. 프로토타입 HTML의 함수를 Node로 직접 실행해 재샘플 고도와 구간 표가 같은지 비교합니다(샘플 코스, 왕복 코스, 가상 100 km 코스, 설정 여러 조합).

### 3.2 코스 서버 (GitHub Pages)

| 경로 | 내용 |
|---|---|
| `current.txt` | 현재 코스 ID 한 줄 |
| `index.txt` | `<id>\t<이름>\t<길이 m>\t<누적 상승 m>\t<조각 수>` 줄들 |
| `c/<id>/m.txt` | 매니페스트 (`key=value`) |
| `c/<id>/<i>.txt` | Base64 조각 |
| `c/<id>/preview.png` | 확인용 그림 |

- `gpx/`, `trailgrade/`, `pages/` 등이 바뀌어 푸시되면 변환기 시험 → 변환 → 배포 순서로 자동 실행됩니다(`--order git`: 가장 최근에 커밋한 GPX가 현재 코스).
- `Content-Type: text/plain; charset=utf-8`, 리다이렉트 없음. **실기기에서 받기 성공**을 사진으로 확인했습니다(코스 메뉴에 서버 코스 이름이 나옴).

### 3.3 코스 받기·저장·복원 (`CourseSync`, `CourseStore`, `TrailCourse`)

동작 순서: `current.txt` → `m.txt` → 조각 0…N−1 → 복원·검증 → 활성 코스 교체.

| 규칙 | 내용 | 확인 |
|---|---|---|
| 시작 시점 | 활동 화면이 열릴 때(타이머 시작 전) 한 번 | **실기기**(시험 필드: 타이머 OFF 상태에서 웹 요청 200) |
| 요청 방식 | 한 번에 하나, `compute()`에서만 시작, 콜백은 결과만 기록. 조각당 최대 3회·5초 간격 재시도, 응답 60초 제한 | 시뮬레이터 |
| 끊겼을 때 | 진행 번호(`dl`)를 저장해 다음 활동에서 이어받음. 그동안 기존 코스로 계속 그림 | 시뮬레이터 |
| 검증 | 조각을 합치며 SHA-256을 계산해 앞 10자리가 코스 ID와 같을 때만 적용. 손상되면 받은 조각을 지우고 기존 코스 유지 | 시뮬레이터 |
| 저장 | 조각은 받자마자 Base64를 풀어 **ByteArray로 저장**. 활성 코스와 직전 코스만 보관 | **실기기**(ByteArray 저장 OK, 총량 320 KB 이상) |
| 복원 | 조각을 하나로 합치지 않고 **조각 배열 그대로** 읽음(합치면 순간 메모리가 두 배) | 시뮬레이터 |
| 코스 전환 | 저장된 다른 코스를 고르면 다시 받지 않고 불러옴. 새 코스를 검증·불러오기 직전에 기존 코스를 메모리에서 내려놓음 | 시뮬레이터 |
| 폰 없이 | 저장된 코스로 바로 그림 | 시뮬레이터 |
| 오류 표시 | `폰 연결 없음`, `응답이 너무 큼`, `메모리 부족`, `HTTPS 오류`, `응답 없음`, `파일 없음 (404)`, `저장 공간 부족`, `코스 검증 실패`(코드 포함). 5초 표시 | 시뮬레이터 |

### 3.4 위치 결정 (`PositionTracker`, `CourseGeo`)

결과는 코스 위치 d(m), 위치 출처, 코스 이탈 여부입니다. 우선순위:

1. **가민 코스 내비게이션 축** — `d = L × (1 − distanceToDestination / 가민 코스 총길이)`. 가민 코스 총길이는 본 값 중 최댓값. 저장 코스 길이와 ±2% 안이고 `distanceToNextPoint`와 다를 때만 사용(예전 펌웨어 버그 대비). 이탈은 `offCourseDistance`로 판단.
2. **GPS 좌표 매칭** — 직전 위치 −200 m ~ +1 km 창에서 가장 가까운 선분에 투영. 처음이거나 30초 넘게 이탈했으면 코스 전체 탐색(체크포인트 3곳 후보). 왕복 구간에서 옆 길로 튀지 않게 이동 거리 벌점을 둠(뒤로 20 m, 앞으로 50 m + 6 m/s × 경과 시간을 넘으면 넘은 거리 × 0.2, 모든 후보에 거리 × 0.05).
3. **누적 거리** — `elapsedDistance`(출발점이 코스 시작이라고 가정).

코스 이탈: 최근접 거리가 임계값(설정, 기본 50 m)을 넘으면 이탈. 마지막 매칭 위치를 유지합니다.

시험 재생(가상 러너가 코스를 따라 20 m마다 위치 입력을 만들어 넣음)으로 확인한 결과 — **시뮬레이터**:

| 상황 | 출처 | 오차 중앙값 / 최대 | 뒤로 튐 |
|---|---|---|---|
| GPS만, 85 m 옆으로 이탈했다 복귀 (샘플 21.6 km, 왕복 구간 포함) | GPS | 2.2 m / 29.3 m | 없음 |
| 가민 코스(길이 1% 김) | 가민 | 0.9 m / 2.1 m | 없음 |
| 가민 남은 거리 = 다음 지점까지 거리 (버그 흉내) | GPS로 전환 | 2.4 m / 7.6 m | 없음 |
| 가민 코스 총길이 90% (다른 코스) | GPS로 전환 | 1.8 m / 8.5 m | 없음 |

**미확인(실기기)**: 실제 가민 코스를 따라갈 때 `distanceToDestination`이 어떤 값으로 들어오는지, `nameOfDestination`이 코스 이름인지(명세 10.1 9번). 진단 표시로 확인합니다.

### 3.5 화면 모드 (오르막·내리막·평지)
- 코스 위치가 속한 구간의 유형으로 모드를 정합니다.
- 이웃 구간으로 넘어갈 때는 **새 구간으로 30 m 들어간 뒤** 전환(되돌아갈 때도 같음). 두 구간 이상 건너뛰면 즉시 전환. — 시험 재생에서 전환 14회 모두 30 m 뒤에 일어남(**시뮬레이터**).

그래프

- **가로 범위 고정**(500 m, 1, 2, 5, 10 km): 현재 위치를 왼쪽 25%에 두고 앞 75%. 가로·세로 축척(px/m)이 모든 화면에서 같음. 세로 위치는 다 들어가면 바닥 맞춤, 넘치면 현재 위치가 화면 안에 있도록 앞쪽을 우선해 잘라냄. 위로 잘리면 오른쪽 위에 ▲, 아래로 잘리면 오른쪽 아래에 ▼ 삼각형.
- **구간 맞춤**: 현재 구간 + 여백, 가로·세로 비율을 고정한 채 함께 축소(contain).
- 열(1 px)마다 고도를 보간해 채움. 색은 그 지점 60 m 창의 경사로 정함. 지나온 부분은 절반 밝기.
- 윤곽선: 강조 범위 `#e8e8e8`, 그 밖 `#4a4a4a`. 기준선 `#2c2c2c`.
- 구간 끝(또는 다음 구간 시작, 도착) 점: 오르막 `#fe6a00`, 내리막 `#1888ff`, 도착 흰색. **글자 레이블 없음.**
- 현재 위치: 꼭짓점이 프로파일에 닿는 아래 방향 붉은 삼각형(`#ff1f1f`). 코스 이탈 중에는 주황(`#fab219`) 테두리만.

경사 색 3단계 (절대값 기준, 방향은 색 계열로 구분)

| 경사 | 0–10% | 10–20% | 20% 이상 |
|---|---|---|---|
| 오르막 | `#00df3f` 초록 | `#fefc00` 노랑 | `#e00041` 빨강 |

수치 정의 (변환기가 평활화한 코스 데이터 기준)

| 수치 | 정의 |
|---|---|
| 현재 경사 | `(ele(d+w/2) − ele(d−w/2)) / w × 100`, w는 설정(기본 100 m), 코스 끝에서는 범위를 안으로 자름. 정수로 반올림, 부호 `+`/`−`(U+2212) |
| 평균 | 구간 순 고도 변화 ÷ 길이 × 100 |
| 최대 | d부터 구간 끝까지 100 m 창 경사의 최댓값(내리막은 절댓값) |
| 남은 상승·하강 | d부터 구간 끝까지 오르는(내리는) 변화만 더함 |
| 남은 거리 | 구간 끝 거리 − d (0 미만이면 0) |

### 3.7 설정 (시계 안 설정 메뉴)

활동 설정에서 Connect IQ 필드를 통해 엽니다(`getSettingsView`, **실기기에서 메뉴가 열리고 한글이 표시됨**을 사진으로 확인). 값은 `Application.Storage`에 저장하며 폰 설정에는 기대지 않습니다.

| 항목 | 값 | 기본 |
|---|---|---|
| 세로 배율 | 2×, 3×, 4× | 3× |
| 그래프 가로 범위 | 500 m, 1 km, 2 km, 5 km, 10 km, 구간 맞춤 | 2 km |
| 현재 경사 평균 구간 | 100, 200, 400 m | 100 m |
| 코스 이탈 임계값 | 30, 50, 100 m | 50 m |
| 경사 색상 | 켬, 끔 | 켬 |
| 진단 표시 | 끔, 켬 | 끔 |
| 코스 | 서버 현재 코스 따르기 / 저장된 코스(활성·직전) / 서버 목록(`index.txt`)의 다른 코스 | 서버 따르기 |
| 코스 목록 새로고침 | 서버 `index.txt`를 다시 받음 (처음 한 번은 자동) | |

- 값을 바꾸면 데이터 필드가 다음 `compute()`에서 재시작 없이 반영합니다(**시뮬레이터**). 서버 코스를 고르면 받아서 적용합니다.
- 메뉴 화면: `CustomMenu`로 직접 그림. 좌측 정렬, 주 글자 0.09S·보조 줄 0.08S(36 px)·제목 0.08S, 기본 메뉴의 파란 그라데이션 강조는 검게 덮고 선택한 줄은 흰 글자, 지금 고른 값은 초록 글자. (1.2.0, **시뮬레이터**, 실기기 미확인)
- 변경 번호(`s_ver`)와 새로고침 요청(`s_refresh`)을 Storage에 둡니다(설정 화면이 별도 인스턴스로 도는 경우 대비).

### 3.8 진단 표시 (실기기 시험용)
설정 "진단 표시"를 켜면 그래프 위쪽에 검은 배경 두 줄이 나옵니다.
1줄 `위치 출처(가민/GPS/거리) 코스 위치(km) 남은 메모리`, 2줄 `dtd <가민 남은 거리> (가민 값을 쓰지 않은 이유) <목적지 이름>`. 명세 10.1 9번을 사진으로 확인하는 용도입니다.

### 3.9 한글 처리
- 시계 시스템 글꼴은 언어 설정에 따라 한글이 없을 수 있어 벡터 글꼴을 씁니다.
- 받아 둔 코스 이름의 분리형 한글 자모는 그릴 때 완성형으로 합칩니다(`Hangul.compose`). 자기 시험은 시뮬레이터 로그(`hangul test`)로 확인.

## 4. 데이터 형식

### 4.1 코스 바이너리 (빅엔디언)
- 헤더 20 B: `"TG"`, 버전 u8(=1), 간격 u8(m), 포인트 수 u16, 구간 수 u16, 첫 점 위도 i32·경도 i32(1e-5°), 예약 u32
- 고도 N × u16 (0.1 m) → 좌표 (N−1) × (i16, i16) 델타(1e-5°, 각 점을 반올림한 절대값끼리의 차이) → 구간 레코드 × 10 B (유형 u8, 플래그 u8, 시작 u16, 끝 u16, 순 고도 변화 i16(0.1 m), 평균 경사 i8(0.5%), 최대 경사 u8(0.5%))
- 크기 `20 + 2N + 4(N−1) + 10 × 구간 수`. 샘플 21.6 km = 6,620 B, 100 km ≈ 30.5 KB
- 시계에서는 값이 두 조각에 걸치지 않도록 모든 값이 짝수 위치이고 조각 크기가 짝수입니다.

### 4.2 시계 저장소 (`Application.Storage`)

| 키 | 내용 |
|---|---|
| `active`, `prev` | 활성·직전 코스 ID |
| `m_<id>` | 매니페스트 `{name, bytes, chunks, len, gain, loss, emin, emax, ok}` (검증이 끝나면 `ok=1`) |
| `c_<id>_<i>` | 코스 조각 (ByteArray) |
| `dl` | 받는 중인 코스 `{id, next}` |
| `idx` | 마지막으로 받은 `index.txt` 문자열 |
| `s_exag, s_width, s_gwin, s_off, s_color, s_diag, s_course, s_ver, s_refresh` | 설정 |
